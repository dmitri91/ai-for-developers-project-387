## Сводка проблем

Общее состояние хорошее: Performance и Best Practices на высоком уровне, метрики в зелёной зоне (LCP 1.9s, CLS 0). Основные проблемы — SEO (0.82) и несколько незначительных замечаний по Accessibility и оптимизации.

### SEO (0.82)
- **Нет meta description** — в `<head>` отсутствует мета-тег описания.
- **Некорректный robots.txt** — на `/robots.txt` сервер отдаёт HTML-страницу (SPA-fallback возвращает `index.html`), Lighthouse не может распарсить содержимое. Нужен настоящий `robots.txt`.

### Accessibility (0.94)
- **Недостаточный контраст** — один элемент: кнопка (`.mantine-Button-label` в `div.m_6d731127 > a.mantine-focus-auto`) не проходит по контрасту фона и текста.

### Performance / оптимизация
- **Неиспользуемый JS** — ~75 КБ (55% бандла `index-BrvshHt_.js`).
- **Неиспользуемый CSS** — ~35 КБ (89% файла `index-MgNbK8ar.css`).
- **Кэш ресурсов** — статические ассеты (`index-*.js`, `index-*.css`) отдаются без заголовков кэширования (`cacheLifetimeMs: 0`), экономия при настройке ~175 КБ.
- **Render-blocking CSS** — `index-MgNbK8ar.css` блокирует рендеринг (~300 мс). Замечание «network dependency tree» связано с той же цепочкой загрузки ассетов.

## Рекомендуемые правки (front/)

### Высокий приоритет
1. **Добавить meta description** — прописать в `index.html` (например, краткое описание сервиса записи). Мгновенно закрывает аудит SEO.
2. **Добавить настоящий `robots.txt`** — файл в `front/public/robots.txt` с корректным содержимым (например, разрешить индексацию всех страниц). Сейчас на `/robots.txt` отдаётся HTML.

### Средний приоритет
3. **Настроить кэширование статики** — в конфигурации деплоя (Render) выставить заголовки кэширования для `/assets/*` (иммутабельные, т.к. хэш в имени): `Cache-Control: public, max-age=31536000, immutable`. Экономия ~175 КБ при повторных визитах.
4. **Поправить контраст кнопки** — подобрать цвет текста/фона кнопки-ссылки, проходящий WCAG AA (порог контраста 4.5:1).

### Низкий приоритет
5. **Сократить неиспользуемый JS/CSS** — 75 КБ JS и 35 КБ CSS. Кандидаты: разделение кода (code-splitting по маршрутам), ленивая загрузка неиспользуемых компонентов Mantine. Экономия в основном на первом заходе.
6. **Отложить загрузку CSS** — рассмотреть предзагрузку критического CSS inline и асинхронную загрузку остального, чтобы убрать render-blocking (~300 мс).

Оценки Performance (0.98) и Best Practices (1.00) в доработке не нуждаются.
